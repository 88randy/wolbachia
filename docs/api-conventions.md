# API conventions (mobile + web)

Single contract for every client. Source of truth: OpenAPI schema generated by drf-spectacular; `packages/api-client` is generated from it (`npm run api:generate`), and CI fails a PR whose committed schema or client is stale.

| Topic | Convention | Status |
|---|---|---|
| Base path | `/api/v1/`. Field-only endpoints under `/api/v1/field/` (sync, catalog snapshot, rules snapshot, uploads). | Accepted |
| Naming | Plural kebab-case English nouns; actions as `POST /<resource>/{id}/<verb>/`. | Accepted |
| Organization | Resolved from the authenticated user's membership. Any `organization_id` in the body is ignored. Objects of another org → `404`. | Accepted |
| Multi-org users | Active org chosen with header `X-Organization: <slug>`; required only if the user has more than one active membership (else `400 organization_header_required`). A slug that is not one of the user's active memberships is always `403 no_active_membership`, even for users with one membership. Active = membership and organization both `is_active`. | Accepted |
| No delete | No `DELETE` on business data. `POST …/void/` with `{reason}`; responses carry `voided_at`, `voided_by`, `void_reason`; lists exclude voided unless `?include_voided=true`. `PUT`/`PATCH` on a voided record → `409 already_voided`. Mobile uses a void event in the sync batch with the same semantics. | Accepted |
| Void reason (#32) | One validator for every void path (`POST …/void/`, rule parameter versions, the phone's `record.void` event and `void_record`): the reason is trimmed and must have at least `VOID_REASON_MIN_LENGTH` characters (default 10, counted as Unicode code points) and at most 1000. Too short or blank text: `400 validation_error` with `fields.reason: [{code: "void_reason_too_short", params: {min_length}}]`; a missing reason keeps `required`, a longer one `max_length`. The stored reason is the trimmed text. `GET /me/` returns `limits: {void_reason_min_length, void_reason_max_length}` so the web mirrors the values; the server answer always wins. A bad body is a `400` even when the record could not be voided anyway (checked before the state). In a sync batch the event is `rejected` with `invalid_payload` and `params.fields.reason: ["void_reason_too_short"]`. Other void answers: `409 already_voided`, `409` for a record that cannot be voided now, `403`, `404`. | Accepted |
| Blocked actions | `409` + `{ "blocked_by": [{ "reason", "unblocked_by_role", "link" }] }`. | Accepted |
| Errors | Every 4xx/5xx body: `{ "code": "<machine_code>", "detail": "<English, for logs>", "fields": { "<field>": [{ "code": "<machine_code>", "params": {} }] } }`. `fields` only on `400`. Clients show text from `packages/i18n` by `code`; `detail` is never shown to users. `409` blocked actions add `blocked_by` (see above). | Accepted |
| OpenAPI contract | `packages/api-client/openapi.yaml` is the committed export (dev settings, `--validate --fail-on-warn`). The `ErrorEnvelope` component (`code`, `detail`, optional `fields` and `blocked_by`) is the `default` response of every operation, so clients type every non-2xx body as the envelope. Page-number lists declare `Paginated<Name>List` with `count`; cursor lists declare the same name without `count` (give a cursor list its own serializer class so the component names do not collide). Any API change in a PR also commits the output of `npm run api:generate`. A change that breaks existing clients (removed or renamed path, field or parameter, a field that becomes required, a narrower type) is marked in the PR template checkbox "API breaking change". | Accepted |
| Paging | Page number (`?page=&page_size=`, response `{count, next, previous, results}`) for admin tables. Cursor (`?cursor=`, response `{next, previous, results}`) for large or streaming lists: sync changes, access log, notifications, field events. Each endpoint declares one style in OpenAPI. | Accepted |
| Objects by code | Human codes (OV-010, B-4471, C-07, I-0236) resolvable via `?code=` on the list endpoint (returns 0 or 1 result). Detail routes use ids. Implemented by `core.filters.CodeLookupFilter`: a viewset opts in with `code_lookup_field = "code"`; exact match (case-sensitive) after trimming surrounding whitespace, only on the `list` action, scoped to the active organization like any list; a repeated `?code=` uses the last value; a blank value, one longer than 50 characters or one with NUL characters is `400 validation_error` with `fields.code` (`blank`, `max_length`, `null_characters_not_allowed`). The filter is registered in `DEFAULT_FILTER_BACKENDS`; a viewset that sets its own `filter_backends` must keep it. The "0 or 1 result" guarantee requires `UniqueConstraint(organization, code)` on the model (the code is unique per organization, not globally). Documented per operation in OpenAPI. | Accepted |
| Exports | `GET …/export/?format=csv|pdf`, server-side, logged in access log; personal data blank without transfer authorization. | Accepted |
| Rules | Per-key parameters with versions and `effective_from`; never overwritten. Mobile downloads a snapshot with a `rules_version` hash. | Accepted |
| Catalogs | `/catalogs/{slug}/items/`; "Other (specify)" item is fixed and cannot be deactivated (`409`). | Accepted |
| Auth | Mobile: opaque access + refresh tokens bound to a registered device (`Authorization: Bearer <access>`). Web: Django session cookie + CSRF token (`SameSite=Lax`, `Secure`, `HttpOnly`). Same user model and permissions. Details in the next three rows. | Accepted |
| Live data | Django Channels WebSocket for live shift positions. Path and auth defined in #19. | Pending (#19) |
| User-facing text | The API never returns user-facing text. It returns `code` + `params`; mobile and web translate with `packages/i18n`. Exception: catalog item labels configured per organization (`label_es`, `label_en`) are data. The password reset email is the one other exception: its text lives in backend templates per locale (es-MX default, en), because an email is not an API response. | Accepted |
| Time | All timestamps ISO 8601 UTC; organization timezone and epi week from `/me/`. Field events keep `device_time` + `server_received_at`. | Accepted |
| `GET /me/` | `{ user: {id, username, email, first_name, last_name}, organization: {id, slug, name, country, timezone, languages[], logo_url} \| null, profiles: [{slug, label_es, label_en}], permissions: ["<resource>.<action>"] (sorted, unique, union of active profiles), scope: {centers: [], quadrants: []}, organizations: [{slug, name}], limits: {void_reason_min_length, void_reason_max_length} }`. Exempt from the multi-membership `400`: with several memberships and no header, `organization` is `null`, `profiles`/`permissions` are empty and `organizations` lists the choices. No active membership → `403 no_active_membership`. Epi week is added when its rule exists. | Accepted |
| `GET /health/` | `{"status": "ok"}`; no authentication, no organization, no throttling. | Accepted |
| Error codes (#2) | `validation_error` (400, with `fields`), `parse_error` (400), `organization_header_required` (400), `profile_organization_mismatch` (400), `not_authenticated` (401), `permission_denied` (403), `no_active_membership` (403), `not_found` (404), `method_not_allowed` (405), `already_voided` (409), `throttled` (429, with `Retry-After`), `server_error` (500). Field error `params` is `{}` until a rule needs parameters. Unauthenticated requests are `401` (session auth sends `WWW-Authenticate: Session`). | Accepted |
| OPTIONS | Denied (`403`) on scoped resources: there is no permission code for `metadata`, so serializer metadata is not exposed. | Accepted |
| Permissions | A profile holds permission codes `<resource>.<action>`; a view declares `required_permissions` (action → code) and DRF `HasPermissionCode` checks the code of the current action against the union of the user's active profiles in the active organization. | Accepted |
| Field snapshots (#3) | `GET /field/catalog/` and `GET /field/rules/` return the whole configuration in one compact body with a `version` (SHA-256 of the canonical JSON of the content). The same value is the `ETag` (`"<version>"`); `Cache-Control: private, no-cache`; `Vary: X-Organization` (the answer depends on the active organization). A matching `If-None-Match` (weak `W/` prefix and `*` accepted) gets `304` with no body, after authentication and permissions are checked. Catalog snapshot: `{version, catalogs: [{slug, label_es, label_en, is_open, items: [{id, code, label_es, label_en, icon, sort, is_other, requires_photo}]}]}`, active items only, "Other" last; a blank `label_en` means "use `label_es`". Rules snapshot: `{version, next_change_at, parameters: [{key, value_type, unit, value, effective_from, version_id}]}`; `value` is a JSON number, or `null` when the parameter has no value yet ("not configured"); versions scheduled for later and voided versions are left out, and the earliest scheduled one is `next_change_at` (it is part of the hash). The `version` is a consistency token: the values that applied at a past instant come from the version history, not from the hash. Mobile refreshes when sync reports a new `catalog_version` / `rules_version` (#5), on login (`If-None-Match`) and when `next_change_at` passes. | Accepted |
| Rule parameters (#3) | `GET /rule-parameters/` and `GET /rule-parameters/{key}/` (lookup by key): `{key, value_type: integer\|decimal, unit: m\|km_h\|s\|min\|week\|count\|km_l, min_value, max_value, value, effective_from, version_id, next_change_at}`. `GET /rule-parameters/{key}/versions/` is the full history (voided versions included), newest first, and `GET .../versions/{id}/` one version; each is `{id, value, effective_from, effective_date, reason, status: scheduled\|in_force\|superseded\|voided, created_by, created_at, voided_at, voided_by, void_reason}`. `POST .../versions/` takes `{value, effective_from, reason}` where `effective_from` is a local calendar date (`YYYY-MM-DD`): today takes effect immediately (several versions for today are allowed; the latest `effective_from` wins, so a seeded value can be corrected on day one), a future date at 00:00 in the organization's timezone (at most 365 days ahead, one non-voided version per date), a past date is rejected. `POST .../versions/{id}/void/ {reason}` voids a version that has not taken effect yet (`409 version_not_scheduled` otherwise, `409 already_voided` twice): it stays in the history, leaves the value in force and the snapshots, and frees its date. There is no `PUT`, `PATCH` or `DELETE` on versions (`405`); parameters are created by the seed, so there is no `POST` on `/rule-parameters/`. Parameters are per organization (no regional override). | Accepted |
| Catalog items (#3) | `GET /catalogs/` lists the catalogs (created by the seed, no `POST`). `GET/POST /catalogs/{slug}/items/`, `GET/PATCH /catalogs/{slug}/items/{id}/`; no `PUT` or `DELETE`. `POST` takes `{code, label_es, label_en?, icon?, sort?, requires_photo?}`: `code` is lowercase (`^[a-z0-9][a-z0-9_-]*$`, max 64) and `other` is reserved for the fixed "Other" item; `icon` is `^[a-z0-9-]+$` (max 64); `sort` is 0 to 10000, and an omitted `sort` appends the item before "Other". `PATCH` edits labels, icon, `sort` (this is the reorder contract) and `requires_photo`; `code`, `is_other` and `is_active` are ignored. `POST …/deactivate/` and `POST …/activate/` are idempotent. A catalog holds at most 200 active items. A catalog slug or item of another organization is `404`. | Accepted |
| Error codes (#3) | Field errors (`400 validation_error`, `fields`): `duplicate_code` and `reserved_code` (item `code`), `sort_exhausted` (item `sort`), `effective_from_in_past`, `effective_from_too_far` and `duplicate_effective_date` (version `effective_from`), `not_an_integer` and `out_of_range` (version `value`; `out_of_range` params are `{min, max}`, `null` when unbounded). Plus `409 other_item_cannot_be_deactivated`, `409 catalog_item_limit_reached` and `409 version_not_scheduled`. Services raise `core.exceptions.FieldValidationError` to report a coded field error with `params`. | Accepted |
| Permission codes (#3) | `catalog.read`, `catalog_item.create`, `catalog_item.update`, `catalog_item.deactivate`, `catalog_item.activate`, `rule_parameter.read` (parameter list and snapshot), `rule_parameter_version.read` (history), `rule_parameter_version.create`, `rule_parameter_version.void`. Seeded once per profile created by the seed: `admin` all; `courier`, `supervisor`, `entomologist`, `community_promoter` `catalog.read` and `rule_parameter.read` (the field snapshots need them). Admin lists of items also run under `catalog.read`. | Accepted |
| Auth endpoints (#4) | `GET /auth/csrf/` `204` + CSRF cookie. `POST /auth/login/` `{username, password, device_id?, app_version?, label?}`: with `device_id` (mobile) `200 {access, refresh, me, server_time}` and the `Device` is registered or updated in the active organization; without it (web) `200 {me, server_time}` + session cookie, CSRF enforced (`403 permission_denied` without it; send the cookie value as `X-CSRFToken`). `POST /auth/refresh/` `{refresh, device_id}` `200 {access, refresh, server_time}`. `POST /auth/logout/` `204`, idempotent (web: ends the session, CSRF enforced; mobile: revokes the session, also with an expired token). `POST /auth/password-reset/` `{email}` `202` with an empty body, always. `POST /auth/password-reset/confirm/` `{uid, token, new_password}` `204`. Token responses are `Cache-Control: no-store`. | Accepted |
| Tokens (#4) | Opaque random tokens, stored only as SHA-256 digests in `TokenPair` rows (one per issued pair, never deleted). Access: 15 min. Refresh: 30 days idle, single use: exchanging it consumes the pair and issues a child pair. A consumed refresh token presented again inside 60 s is a lost response and is accepted once more (a sibling pair; every pair issued in the window stays valid, and the replaced access token works until the window closes) **only if no token issued after it has been used**; and the parent has fewer than 3 children; otherwise, outside the window, the whole session is revoked; beyond the cap the duplicate is refused with `429 throttled` and `Retry-After` until the window closes, without revoking (`refresh_reuse`, logged `refresh_reuse_detected`; accepted duplicates are logged `refresh_grace_retry`). Per parent only the first sibling ever used (access token used or refresh exchanged) is valid: using or refreshing another sibling afterwards revokes the session (`refresh_reuse`). Logout and the final upload also require the current pair (not replaced beyond the window, not a retired sibling). Refresh also revokes the session when the user is deactivated or the pinned membership ended. A mobile session pins its organization: `X-Organization` naming another one is `403 no_active_membership`. A login on a device supersedes the user's earlier sessions on it (`superseded`). Lifetimes are env settings [PENDING client]. | Accepted |
| Devices and revocation (#4) | `GET /devices/` (`?is_revoked=`, `?user=`, page-number paging) and `GET /devices/{id}/` need `device.read`; `POST /devices/{id}/revoke/` needs `device.revoke` (lost phone: the device cannot log in again, its sessions are revoked, idempotent); `POST /users/{id}/revoke-device-sessions/` needs `user.revoke_device_sessions` and answers `200 {revoked_sessions}` (only that organization's sessions; a user with no membership in the organization is `404`). Both revoke endpoints take an optional `{allow_final_upload: bool}` (default `false`). A revoked session is `401 session_revoked` on the next request. **Final upload:** only when an administrator revokes with `allow_final_upload: true` (reasons `admin_revoke` or `device_revoked`), the phone may make one more upload on views that use `accounts.final_upload.FinalUploadMixin` (`/field/sync/` in #5), until `AUTH_REVOKED_FINAL_UPLOAD_HOURS` after the revoke. The mixin spends it in the request's transaction (a failed request gives it back), answers `X-Session-Revoked: true` and sets `is_final_upload`: #5 marks those events `in_review`. A password change withdraws every pending final upload. | Accepted |
| Error codes (#4) | `401`: `invalid_credentials` (bad password, unknown or inactive user: always the same), `invalid_token` (unknown, malformed, wrong `device_id`), `token_expired`, `session_revoked`. `403`: `device_revoked`, `device_organization_mismatch`. `400`: `invalid_reset_token` (also for expired, used or tampered links), plus `validation_error` with the password validator codes in `fields.new_password` (`password_too_short`, `password_too_common`, `password_entirely_numeric`, `password_too_similar`). `429 throttled` for rate limits and lockout, with `Retry-After`. A `401` about a bearer token (`invalid_token`, `token_expired`, `session_revoked`) carries `WWW-Authenticate: Bearer`; other 401s carry `Session`. A view whose first authenticator is the bearer one (`/field/sync/`) also answers a request with no credentials `401 not_authenticated` with `WWW-Authenticate: Bearer` (not `Session`). | Accepted |
| Login protection (#4) | Rate limits per username + address (10/min) and per address (30/min) on login, 30/min on refresh, 5/hour on reset requests and 20/hour on reset confirmations: keyed by DRF `get_ident`, so `X-Forwarded-For` counts only up to `DRF_NUM_PROXIES` (required in production). Lockout: 5 failures per username + address in 15 min lock that pair for 15 min (even with the right password); failures for unknown usernames count too. Reset emails: at most 3 per address and hour (`AUTH_PASSWORD_RESET_EMAILS_PER_ADDRESS_PER_HOUR`); trade-off: whoever knows an address can use its quota and delay the owner's reset until the hour passes. Auth events go to the structured logger `accounts.auth` (`login_succeeded`, `login_failed`, `login_locked_out`, `login_refused` with its `reason`, `refresh`, `refresh_grace_retry`, `refresh_reuse_detected`, `logout`, `sessions_revoked`, `device_revoked`, `password_reset_*`; organization, user, device, IP, keyed username fingerprint; never passwords, tokens or emails). | Accepted |
| Field sync (#5) | `POST /field/sync/` uploads a sync batch and pulls changes in one request: bearer device token only, permission `field_event.sync`, body `{device_id, sent_at, cursor?, events: [{id, type, schema_version, device_time, payload, shift_id?, gps?, rules_version, catalog_version, manual_capture, voids_event_id?}]}`, answer `{server_time, results: [{id, status, code, params}], changes: {cursor, reviews, catalog_version, rules_version, has_more}}`. Idempotent by event id, one batch per courier at a time (`429 sync_in_progress`), per-event results in request order, clock skew measured with `sent_at`, strict signed cursor, final upload from a revoked session lands `in_review` with `X-Session-Revoked: true`. Full contract, code tables, limits and the handler registry: [`sync.md`](sync.md). | Accepted |
| Error codes (#5) | Batch: `400 invalid_cursor`, `403 device_mismatch`, `413 payload_too_large` (body bytes, more than `SYNC_MAX_EVENTS` events, or Django's own body limit), `429 throttled` per device, `429 sync_in_progress` (another batch of the same courier is running; `Retry-After`). Per event (`results[].code`): `unsupported_event_type`, `unsupported_schema_version`, `invalid_payload`, `event_payload_too_large`, `event_id_conflict`, `void_target_not_found`, `void_target_not_owned`, `already_voided` (`rejected`); `clock_skew`, `final_upload_after_revoke` (`in_review`); `accepted`. Translated by the phone from `packages/i18n` (`sync.result.*`, `sync.batch.*`). | Accepted |
| Review items (#5) | `GET /review-items/` (permission `review_item.read`; cursor paging, newest first; `?kind=rejected\|in_review`, `?code=`): `{id, event_id, event_type, kind, code, params, courier, device, created_at}`. Read-only: review decisions (accept, void, open incident) are #22. | Accepted |
| Permission codes (#5) | `field_event.sync` (seeded for `courier`), `review_item.read` (seeded for `supervisor` and `admin`). | Accepted |
| Shifts (#68) | `GET /shifts/` (page-number paging; `?status=open\|closed`, `?courier=<user id>`, `?date_from=` and `?date_to=` as `YYYY-MM-DD`, inclusive, in the organization's time zone, on the phone's opening time; `date_to` before `date_from` is `400 validation_error` with `fields.date_to` `date_range_inverted`) and `GET /shifts/{id}/` need `shift.read`; newest first. Shift: `{id, courier, device, motorcycle, motorcycle_code, status, opened_at_device, opened_event, odometer_open_km, open_note, closed_at_device, closed_event, odometer_close_km, close_note, checks: [{id, item, item_code, result, note}], created_at}`. Read-only: shifts are written by the `shift.open` / `shift.close` sync events (`sync.md`). No human code (`?code=`) yet: shifts are identified by the UUID the phone generated [ASSUMPTION]. Another organization's shift is `404`. | Accepted |
| Permission codes (#68) | `shift.read` (seeded for `supervisor` and `admin`). | Accepted |
| Error codes (#68) | Per event (`results[].code`, see `sync.md`): `shift_already_open`, `motorcycle_unknown`, `motorcycle_blocked`, `motorcycle_in_use`, `odometer_out_of_range`, `shift_not_open`, `shift_event_not_voidable` (`rejected`); `odometer_decreased`, `severe_check`, `captured_after_shift_close` (`in_review`). Translated from `packages/i18n` (`sync.result.*`). | Accepted |
