# API conventions (mobile + web)

Single contract for every client. Source of truth: OpenAPI schema generated by drf-spectacular; `packages/api-client` is generated from it (`npm run api:generate`), and CI fails a PR whose committed schema or client is stale.

## Private evidence (#102)

POST /api/v1/field/uploads/ accepts {content_type,size_bytes,sha256}, with optional
client_id (immutable offline evidence UUID) and context {kind: field_event or
motorcycle_fault,id}. The three-field API stages private UNBOUND bytes and confers
no resource access. Known field-event context requires client_id and the exact
declared UUID/author/device. The response is 201
{upload_id,url,method:PUT,headers,expires_at}. url is a relative local API endpoint,
not a public storage URL. Authentication remains required on PUT. Upload-Lease is
a signed, latest-revision ticket valid for 15 minutes; send it and the returned
Content-Type with raw bytes to PUT /field/uploads/{id}/content/ (204).

POST /field/uploads/{id}/renew/ returns 200 {id,state,verified_at} plus the new
authorization fields, retaining upload_id. POST /field/uploads/{id}/finalize/
accepts optional context and returns 200 {id,state,verified_at}; repeated success
returns the same immutable verification fact. States derive from facts:
authorized, received, verified. A received source may finalize after lease expiry.
GET /attachments/{id}/download/ uses that same public upload UUID, requires a
verified single authorized parent binding, rechecks CURRENT parent read/history
scope before/after unlocked file I/O, and returns sanitized bytes with
Cache-Control: private, no-store and X-Content-Type-Options: nosniff. No raw key,
source bytes or durable download capability is exposed. Voided history remains
available under its real parent read policy; revoked/out-of-scope access does not.

Action field.upload is required for authorize/renew/PUT/finalize, plus fresh owner
and device identity. Binding applies current parent action AND center AND applicable
quadrant without combining profile grants. Current parent read authority governs
download, including readers without field.upload. Foreign/unknown references are
404 before the Upload arbiter. Cookie/CSRF and pinned bearer policies are unchanged.
Seeded admin/supervisor/courier receive field.upload once; custom/revoked grants
stay unchanged. These byte endpoints do not accept revoked final-sync entitlement;
retain local files and reauthenticate/re-authorize without recapture (#246).

JPEG/PNG only, <=10 MiB original/sanitized bytes, <=25 MP and one frame. Actual
size/type/original SHA-256 are verified before Pillow metadata removal. Original
and sanitized hashes remain separate. 400 validation_error fields.file codes:
upload_incomplete, upload_too_large (max_bytes), upload_hash_mismatch,
upload_type_mismatch, upload_invalid_image, upload_pixel_limit (max),
upload_animation_not_supported, upload_sanitized_too_large (max_bytes).
Metadata serializer fields use existing required/invalid/invalid_choice/min_value/
max_value codes. 409 codes with safe blocked_by code entries:
upload_identity_conflict, upload_already_bound, upload_lease_invalid,
upload_lease_expired, upload_incomplete. 429 upload_in_progress carries Retry-After:1;
503 upload_storage_unavailable preserves retryability. Fleet adds HTTP-only 409
motorcycle_evidence_not_ready using its existing safe blocked_by shape.

clear_fault now checks verification/binding to its exact fault before effects.
Ovitrap lifecycle and archived requires_photo checks use existing
ovitrap_evidence_required in_review. Check accepts optional evidence_ids default [].
Post-_store linkage preserves pending references independently of effects; finalize
never accepts review or rewrites original status/payload. #113 remains separate.
No new sync result/i18n code. Full lock/race rule and current callers:
../backend/uploads/README.md; mobile transport/check serialization is #246.

## Configuration table queries (#224)

These admin lists use page-number paging. Organization and parent authorization
precede search, filters, ordering and pagination. `search` uses DRF's
case-insensitive partial matching: terms must all match, each in any documented
search field; quoted phrases stay together. Blank search leaves the list unchanged;
NUL is a `400 validation_error` on `fields.search`.

`ordering` accepts comma-separated fields from the exact allowlist below, each
optionally prefixed with `-` for descending. Blank or unsupported terms return
`400 validation_error` on `fields.ordering`; mixed valid/invalid terms are rejected
together. Every ordering appends `id` ascending to resolve ties. PostgreSQL's native
null ordering applies (null last ascending, first descending). Search and ordering
on these lists do not filter detail lookups or mutation actions.

| List under `/api/v1/` | Search fields | Facets | Ordering fields | Default ordering |
| --- | --- | --- | --- | --- |
| `rule-parameters/` | `key` | `unit` (model enum), `value_type=integer\|decimal` | `key`, `unit`, `value_type`, `effective_from` (current projected version, nullable) | `key,id` |
| `rule-parameters/{key}/versions/` | `reason` | Existing `include_voided=true\|false` (default false); `status=scheduled\|in_force\|superseded\|voided` | `effective_from`, `created_at`, `value` | `-effective_from,-created_at,id` |
| `catalogs/` | `slug`, `label_es`, `label_en` | None | `slug`, `label_es`, `label_en` | `slug,id` |
| `catalogs/{slug}/items/` | `code`, `label_es`, `label_en` | `is_active=true\|false` (omitted: both) | `code`, `label_es`, `label_en`, `sort`, `created_at`, `usage_count` | `is_other,sort,code,id` |
| `devices/` | `label`, `serial`, `app_version`, `last_user.username` from a same-organization membership (active or historical) | Existing `is_revoked`, `user` (any historical device session) | `label`, `serial`, `app_version`, `last_seen_at`, `created_at` | `-created_at,id` |

`unit` values are `m`, `km_h`, `s`, `min`, `day`, `week`, `count`, `km_l`.
New choice facets reject blank/unsupported values; `is_active` accepts exactly
lowercase `true` or `false`. Rule history status never expands void visibility:
`status=voided` requires `include_voided=true` to return rows. Item availability is
independent of historical reference counts; filtering never changes catalog
revisions. Items always prepend `is_other` ascending, even for requested descending
orders, so protected Other stays last among matches. A search may omit Other.
Reorder still requires the complete active non-Other id set and the catalog version,
regardless of list query parameters. Field catalog/rules snapshots and their ETags
keep their existing contracts and do not acquire these table filters.

The existing geography identity lists retain their code search/ordering. Their
`quadrants/{id}/versions/`, `blocks/{id}/versions/` and
`sampling-points/{id}/versions/` actions now support the following independent
history query parameters after resolving the authorized parent:

| History | Filters | `ordering` (one field, optional `-`) | Default |
| --- | --- | --- | --- |
| Quadrant / block | `revision` (positive integer), `created_by` (UUID), `effective_from_from` (inclusive ISO datetime), `effective_from_before` (exclusive ISO datetime) | `revision`, `effective_from`, `created_at`, `created_by` | `-revision,id` |
| Sampling point | `version` (positive integer), `created_by`, the same datetime bounds, `is_retired=true\|false` | `version`, `effective_from`, `created_at`, `created_by`, `is_retired` | `-version,id` |

Both history styles append `id` ascending for ties and paginate after filtering.
An end bound at/before a start bound returns `400` with
`fields.effective_from_before` code `invalid_range`. Invalid UUIDs, dates, positive
integers, booleans and ordering choices use the existing coded validation envelope.
An unmatched author returns an empty history; an unknown or inaccessible parent
returns `404` before any history query. These immutable geography versions have no
void flag or free-text search field; geometry/location are not searched. Their
OpenAPI parameters describe history fields, without the identity-list filters.

Verified primitives: [DRF search and ordering filters](https://www.django-rest-framework.org/api-guide/filtering/)
and [Django queryset ordering](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#order-by).

## Shared conventions

| Topic | Convention | Status |
|---|---|---|
| Base path | `/api/v1/`. Field-only endpoints under `/api/v1/field/` (sync, catalog snapshot, rules snapshot, uploads). | Accepted |
| Naming | Plural kebab-case English nouns; actions as `POST /<resource>/{id}/<verb>/`. | Accepted |
| Organization | Resolved from the authenticated user's membership. Any `organization_id` in the body is ignored. Objects of another org → `404`. | Accepted |
| Multi-org users | Active org chosen with header `X-Organization: <slug>`; required only if the user has more than one active membership (else `400 organization_header_required`). A slug that is not one of the user's active memberships is always `403 no_active_membership`, even for users with one membership. Active = membership and organization both `is_active`. | Accepted |
| No delete | No `DELETE` on business data. `POST …/void/` with `{reason_code, reason?}`; responses carry `voided_at`, `voided_by`, `void_reason_code`, `void_reason`; lists exclude voided unless `?include_voided=true`. `PUT`/`PATCH` on a voided record → `409 already_voided`. Mobile uses a void event in the sync batch with the same semantics. | Accepted |
| Void reason (#32, #80) | Every void path resolves `reason_code` in the target organization's open `void-reason` catalog (one query). A missing or blank code is `required` on `reason_code`; unknown, foreign, missing-catalog or inactive choices return `void_reason_code_unknown` on that field. `other` requires nonblank `reason` (`void_reason_required_for_other` otherwise); the existing visible-character minimum (`VOID_REASON_MIN_LENGTH`, default 10) applies only to Other. Other codes allow an optional note, including an empty one, without a minimum. All nonblank notes are normalized (NFC, CRLF as LF), trimmed, checked for control/bidi characters and limited to 1000 characters. Invisible characters and fillers do not count toward the Other minimum (see `core/void_reason.py`). Text errors remain `void_reason_too_short` with `{min_length}`, `void_reason_invalid_characters`, and `max_length` with `{max_length}`. HTTP errors are `400 validation_error` with `fields.<field>: [{code, params}]`, never user text; validation precedes state checks. Both code and text are stored; old voids are backfilled as `other` with their original text. `GET /me/` still returns `limits: {void_reason_min_length, void_reason_max_length}`. In sync, unknown/foreign codes are rejected with `void_reason_code_unknown`; text errors use `invalid_payload` with `params.fields` and, when applicable, `params.field_params`. A code deactivated since the phone's snapshot lands `in_review` as `void_reason_code_deactivated`, with the target intact until supervisor acceptance (#22). Other void answers remain `409 already_voided`, state conflicts, `403` and `404`. | Accepted |
| Blocked actions | `409` + `{ "blocked_by": [{ "reason", "unblocked_by_role", "link" }] }`. | Accepted |
| Errors | Every 4xx/5xx body: `{ "code": "<machine_code>", "detail": "<English, for logs>", "fields": { "<field>": [{ "code": "<machine_code>", "params": {} }] } }`. `fields` only on `400`. Clients show text from `packages/i18n` by `code`; `detail` is never shown to users. `409` blocked actions add `blocked_by` (see above). | Accepted |
| OpenAPI contract | `packages/api-client/openapi.yaml` is the committed export (dev settings, `--validate --fail-on-warn`). The `ErrorEnvelope` component (`code`, `detail`, optional `fields` and `blocked_by`) is the `default` response of every operation, so clients type every non-2xx body as the envelope. Page-number lists declare `Paginated<Name>List` with `count`; cursor lists declare the same name without `count` (give a cursor list its own serializer class so the component names do not collide). Any API change in a PR also commits the output of `npm run api:generate`. A change that breaks existing clients (removed or renamed path, field or parameter, a field that becomes required, a narrower type) is marked in the PR template checkbox "API breaking change". | Accepted |
| Paging | Page number (`?page=&page_size=`, response `{count, next, previous, results}`) for admin tables. Cursor (`?cursor=`, response `{next, previous, results}`) for large or streaming lists: sync changes, access log, notifications, field events. Each endpoint declares one style in OpenAPI. | Accepted |
| Objects by code | Human codes (OV-010, B-4471, C-07, I-0236) resolvable via `?code=` on the list endpoint (returns 0 or 1 result). Detail routes use ids. Implemented by `core.filters.CodeLookupFilter`: a viewset opts in with `code_lookup_field = "code"`; exact match (case-sensitive) after trimming surrounding whitespace, only on the `list` action, scoped to the active organization like any list; a repeated `?code=` uses the last value; a blank value, one longer than 50 characters or one with NUL characters is `400 validation_error` with `fields.code` (`blank`, `max_length`, `null_characters_not_allowed`). The filter is registered in `DEFAULT_FILTER_BACKENDS`; a viewset that sets its own `filter_backends` must keep it. The "0 or 1 result" guarantee requires `UniqueConstraint(organization, code)` on the model (the code is unique per organization, not globally). Documented per operation in OpenAPI. | Accepted |
| Exports | `GET …/export/?format=csv|pdf`, server-side, logged in access log; personal data blank without transfer authorization. **Open point (found in #29, for the first backend `/export/` issue; not decided here):** `format` is also DRF's default `URL_FORMAT_OVERRIDE`, so `?format=csv` is read by content negotiation before the view runs. The first `/export/` endpoint must register a CSV renderer (and a PDF one), or this convention must rename the parameter (e.g. `?file=csv`). The web client (`web/src/data-table/request-export.ts`) sends `format=csv` and changes in one place. | Accepted |
| Rules | Per-key parameters with versions and `effective_from`; never overwritten. Mobile downloads a snapshot with a `rules_version` hash. | Accepted |
| Catalogs | `/catalogs/{slug}/items/`; "Other (specify)" item is fixed and cannot be deactivated (`409`). | Accepted |
| Auth | Mobile: opaque access + refresh tokens bound to a registered device (`Authorization: Bearer <access>`). Web: Django session cookie + CSRF token (`SameSite=Lax`, `Secure`, `HttpOnly`). Same user model and permissions. Details in the next three rows. | Accepted |
| Live data | Django Channels WebSocket for live shift positions. Path and auth defined in #19. | Pending (#19) |
| User-facing text | The API never returns user-facing text. It returns `code` + `params`; mobile and web translate with `packages/i18n`. Exception: catalog item labels configured per organization (`label_es`, `label_en`) are data. The password reset email is the one other exception: its text lives in backend templates per locale (es-MX default, en), because an email is not an API response. | Accepted |
| Time | All timestamps ISO 8601 UTC; organization timezone and epi week from `/me/`. Field events keep `device_time` + `server_received_at`. | Accepted |
| Session identity (#82) | Every authenticated `/api/v1/` response (session or device token) carries `X-Session-Identity`: an opaque 128-bit HMAC-SHA-256 (key derived from `SECRET_KEY`) of user id + active organization id + session id (`core/session_identity.py`). It is a pseudonymous per-session identifier, not reversible and not forgeable by a client (it is derived from personal identifiers, so treat it as pseudonymous data: it stays out of logs and URLs). It changes with the user, the organization (`X-Organization`; for `/me/` the active one, empty when several memberships and no header) and the session (every login is a new session). Anonymous and non-`/api/v1/` responses do not carry it, and neither do error answers where the organization was not resolved (403 `no_active_membership`, 400 `organization_header_required`, 404, 405): the client compares only successful (2xx) answers, which are the ones that carry data. The login answer carries the identity of the session it just created (including the organization named by `X-Organization`), so it equals the one of `/me/` and of every resource afterwards. **Cross-origin deployments** (web and API on different origins) must add `X-Session-Identity` to `Access-Control-Expose-Headers`, or the browser hides it from the client. All browser tabs share one session cookie, so a client cannot know from its own state which identity a response belongs to; the web client compares the header with the one it holds (taken from the accepted `/me/`) and discards a response that does not match. Not declared per operation in OpenAPI (it would be repeated on every response); documented here. | Accepted |
| `GET /me/` | `{ user: {id, username, email, first_name, last_name}, organization: {id, slug, name, country, timezone, languages[], epi_week: iso\|mmwr, label_phone, support_contact, logo_url} \| null, profiles: [{slug, label_es, label_en}], permissions: ["<resource>.<action>"] (sorted, unique, union of active profiles), scope: {centers: {mode: none\|selected\|all, ids: []}, quadrants: {mode: none\|selected\|all, ids: []}}, organizations: [{slug, name}], limits: {void_reason_min_length, void_reason_max_length} }`. Exempt from the multi-membership `400`: with several memberships and no header, `organization` is `null`, `profiles`/`permissions` are empty and `organizations` lists the choices. No active membership → `403 no_active_membership`. Epi week and support_contact are current organization settings; logo_url is null until a validated raster exists. | Accepted |
| `GET /health/` | `{"status": "ok"}`; no authentication, no organization, no throttling. | Accepted |
| Error codes (#2) | `validation_error` (400, with `fields`), `parse_error` (400), `organization_header_required` (400), `profile_organization_mismatch` (400), `not_authenticated` (401), `permission_denied` (403), `no_active_membership` (403), `not_found` (404), `method_not_allowed` (405), `already_voided` (409), `throttled` (429, with `Retry-After`), `server_error` (500). Field error `params` is `{}` until a rule needs parameters. Unauthenticated requests are `401` (session auth sends `WWW-Authenticate: Session`). | Accepted |
| OPTIONS | Denied (`403`) on scoped resources: there is no permission code for `metadata`, so serializer metadata is not exposed. | Accepted |
| Permissions | A profile holds permission codes `<resource>.<action>`; a view declares `required_permissions` (action → code) and DRF `HasPermissionCode` checks the code of the current action against the union of the user's active profiles in the active organization. | Accepted |
| Field snapshots (#3) | `GET /field/catalog/` and `GET /field/rules/` return the whole configuration in one compact body with a `version` (SHA-256 of the canonical JSON of the content). The same value is the `ETag` (`"<version>"`); `Cache-Control: private, no-cache`; `Vary: X-Organization` (the answer depends on the active organization). A matching `If-None-Match` (weak `W/` prefix and `*` accepted) gets `304` with no body, after authentication and permissions are checked. Catalog snapshot: `{version, catalogs: [{slug, label_es, label_en, is_open, items: [{id, code, label_es, label_en, icon, sort, is_other, requires_photo}]}]}`, active items only, "Other" last; a blank `label_en` means "use `label_es`". Rules snapshot: `{version, next_change_at, parameters: [{key, value_type, unit, value, effective_from, version_id}]}`; `value` is a JSON number, or `null` when the parameter has no value yet ("not configured"); versions scheduled for later and voided versions are left out, and the earliest scheduled one is `next_change_at` (it is part of the hash). The `version` is a consistency token: the values that applied at a past instant come from the version history, not from the hash. Mobile refreshes when sync reports a new `catalog_version` / `rules_version` (#5), on login (`If-None-Match`) and when `next_change_at` passes. | Accepted |
| Rule parameters (#3) | `GET /rule-parameters/` and `GET /rule-parameters/{key}/` (lookup by key): `{key, value_type: integer\|decimal, unit: m\|km_h\|s\|min\|day\|week\|count\|km_l, min_value, max_value, value, effective_from, version_id, next_change_at}`. `GET /rule-parameters/{key}/versions/` is the history, newest first (voided versions only with `?include_voided=true`; any value other than `true` or `false` is `400 validation_error` with `fields.include_voided`; the filter runs before paging), and `GET .../versions/{id}/` one version; each is `{id, value, effective_from, effective_date, reason, status: scheduled\|in_force\|superseded\|voided, created_by, created_by_username, created_at, voided_at, voided_by, voided_by_username, void_reason_code, void_reason}` (usernames are the only author data exposed, are `null` for seed versions and are kept for users who left the organization; `GET .../versions/{id}/` returns a voided version regardless of the filter). `POST .../versions/` takes `{value, effective_from, reason}` where `effective_from` is a local calendar date (`YYYY-MM-DD`): today takes effect immediately (several versions for today are allowed; the latest `effective_from` wins, so a seeded value can be corrected on day one), a future date at 00:00 in the organization's timezone (at most 365 days ahead, one non-voided version per date), a past date is rejected. `POST .../versions/{id}/void/ {reason_code, reason?}` voids a version that has not taken effect yet (`409 version_not_scheduled` otherwise, `409 already_voided` twice): it stays in the history, leaves the value in force and the snapshots, and frees its date. There is no `PUT`, `PATCH` or `DELETE` on versions (`405`); parameters are created by the seed, so there is no `POST` on `/rule-parameters/`. Parameters are per organization (no regional override). The seed has 16 parameters; `revisit_interval_days` (integer, unit `day`, default 7, range 1 to 28) comes from decisions OP02/OP03. `pin_max_attempts` (#209) is an integer count, default 3, inclusive range 1 to 10, delivered through the existing rules snapshot; rerunning `seed_organization_defaults --apply` adds it to older organizations without overwriting their versions. | Accepted |
| Catalog items (#3) | `GET /catalogs/` lists catalogs with integer `version` (created by the seed, no `POST`). Item reads add read-only integer `catalog_version` (same-read catalog revision), `usage_count`, compatible `in_use`, `created_by`/`created_by_username`, nullable `deactivated_at`, `deactivated_by`/`deactivated_by_username` (#182). `GET/POST /catalogs/{slug}/items/`, `GET/PATCH /catalogs/{slug}/items/{id}/`; no `PUT` or `DELETE`. `POST` takes `{code, label_es, label_en?, icon?, sort?, requires_photo?}`: `code` is lowercase (`^[a-z0-9][a-z0-9_-]*$`, max 64) and `other` is reserved for the fixed "Other" item; `icon` is `^[a-z0-9-]+$` (max 64); `sort` is 0 to 10000, and an omitted `sort` appends after active non-Other items (inactive sorts are ignored). `PATCH` edits labels, icon, `sort` (individual edit; atomic reorder uses `POST .../items/reorder/ {version, ordered_ids}`) and `requires_photo`; `code`, `is_other` and `is_active` are ignored. `POST …/deactivate/` and `POST …/activate/` are idempotent. A catalog holds at most 200 active items. A catalog slug or item of another organization is `404`. | Accepted |
| Error codes (#3, #182) | Reorder adds `409 catalog_version_conflict` and `400 validation_error` with `fields.ordered_ids` code `reorder_ids_mismatch`. Field errors (`400 validation_error`, `fields`): `duplicate_code` and `reserved_code` (item `code`), `sort_exhausted` (item `sort`), `effective_from_in_past`, `effective_from_too_far` and `duplicate_effective_date` (version `effective_from`), `not_an_integer` and `out_of_range` (version `value`; `out_of_range` params are `{min, max}`, `null` when unbounded). Plus `409 other_item_cannot_be_deactivated`, `409 catalog_item_limit_reached` and `409 version_not_scheduled`. Services raise `core.exceptions.FieldValidationError` to report a coded field error with `params`. | Accepted |
| Permission codes (#3) | `catalog.read`, `catalog_item.create`, `catalog_item.update`, `catalog_item.deactivate`, `catalog_item.activate`, `rule_parameter.read` (parameter list and snapshot), `rule_parameter_version.read` (history), `rule_parameter_version.create`, `rule_parameter_version.void`. Seeded once per profile created by the seed: `admin` all; `courier`, `supervisor`, `entomologist`, `community_promoter` `catalog.read` and `rule_parameter.read` (the field snapshots need them). Admin lists of items also run under `catalog.read`. | Accepted |
| Auth endpoints (#4) | `GET /auth/csrf/` `204` + CSRF cookie. `POST /auth/login/` `{username, password, device_id?, app_version?, label?}`: with `device_id` (mobile) `200 {access, refresh, me, server_time}` and the `Device` is registered or updated in the active organization; without it (web) `200 {me, server_time}` + session cookie, CSRF enforced (`403 permission_denied` without it; send the cookie value as `X-CSRFToken`). `POST /auth/refresh/` `{refresh, device_id}` `200 {access, refresh, server_time}`. `POST /auth/logout/` `204`, idempotent (web: ends the session, CSRF enforced; mobile: revokes the session, also with an expired token). `POST /auth/password-reset/` `{email}` `202` with an empty body, always. `POST /auth/password-reset/confirm/` `{uid, token, new_password}` `204`. Token responses are `Cache-Control: no-store`. | Accepted |
| Tokens (#4) | Opaque random tokens, stored only as SHA-256 digests in `TokenPair` rows (one per issued pair; live families kept in full, ended families pruned by retention #54, device session audit rows kept). Access: 15 min. Refresh: 30 days idle, single use: exchanging it consumes the pair and issues a child pair. A consumed refresh token presented again inside 60 s is a lost response and is accepted once more (a sibling pair; every pair issued in the window stays valid, and the replaced access token works until the window closes) **only if no token issued after it has been used**; and the parent has fewer than 3 children; otherwise, outside the window, the whole session is revoked; beyond the cap the duplicate is refused with `429 throttled` and `Retry-After` until the window closes, without revoking (`refresh_reuse`, logged `refresh_reuse_detected`; accepted duplicates are logged `refresh_grace_retry`). Per parent only the first sibling ever used (access token used or refresh exchanged) is valid: using or refreshing another sibling afterwards revokes the session (`refresh_reuse`). Logout and the final upload also require the current pair (not replaced beyond the window, not a retired sibling). Refresh also revokes the session when the user is deactivated or the pinned membership ended. A mobile session pins its organization: `X-Organization` naming another one is `403 no_active_membership`. A login on a device supersedes the user's earlier sessions on it (`superseded`). Lifetimes are env settings [PENDING client]. | Accepted |
| Devices and revocation (#4) | `GET /devices/` (`?is_revoked=`, `?user=`, page-number paging) and `GET /devices/{id}/` need `device.read`; `POST /devices/{id}/revoke/` needs `device.revoke` (lost phone: the device cannot log in again, its sessions are revoked, idempotent); `POST /users/{id}/revoke-device-sessions/` needs `user.revoke_device_sessions` and answers `200 {revoked_sessions}` (only that organization's sessions; a user with no membership in the organization is `404`). Both revoke endpoints take an optional `{allow_final_upload: bool}` (default `false`). A revoked session is `401 session_revoked` on the next request. **Final upload:** only when an administrator revokes with `allow_final_upload: true` (reasons `admin_revoke` or `device_revoked`), the phone may make one more upload on views that use `accounts.final_upload.FinalUploadMixin` (`/field/sync/` in #5), until `AUTH_REVOKED_FINAL_UPLOAD_HOURS` after the revoke. ## Organization administration (#99)

`GET /centers/` is a page-number list of active centers visible to center.read,
with `{id, code, name}`, exact `?code=`, `?search=` and `?ordering=code|name`.
`GET /centers/{id}/` also resolves inactive historical centers in scope. Scope is
explicit per dimension: none denies, selected checks its UUID ids (empty denies),
all requires an explicit grant. A new center never expands selected. Permissions,
center and applicable quadrant must be covered by one effective profile grant
intersected with the membership. Org-only configuration checks its action code.
Selected quadrant ids now resolve to real organization/center-owned geography rows (#108); unresolved legacy ids never grant new access.

`GET/PATCH /organization/` reads or versions current name/timezone/languages/
epi_week/label_phone/support_contact. PATCH requires expected_revision; there is no
POST organization creation. `GET /roles/`, `PUT /roles/{id}/permissions/` accepts
`{permissions, scope, expected_revision}`. `GET/POST /memberships/` and
`POST /memberships/{id}/change-scope/` keep shared User identity; create accepts
`{user: UUID, profiles: UUID[], scope}`, change accepts
`{scope, expected_revision, profiles?: UUID[], is_active?: boolean}`. List reads use
role.read, writes role.update; organization settings use organization.read/update.
Membership filters are user, profiles, is_active; ordering/search are server-side.
Foreign or out-of-grant references return 404; absent action grants return 403.
Scope grants cannot exceed the actor's effective grant for the assigned action.
Government is portal.read only, never internal or mixed with internal profiles.

Revisions are monotonic; 409 stale_revision and last_administrator return safe
blocked_by entries. Concurrent administration is serialized per organization;
try-lock contention returns 429 administration_in_progress + Retry-After 1.
Every successful settings/role/membership change appends an immutable authored
configuration snapshot. Baselines and seeds have a null platform author.

`POST /organization/logo/` accepts multipart `{logo, expected_revision}` with
organization.update; `GET` returns authorized same-origin image/png with
organization.read, private/no-store and nosniff. `GET /me/` exposes explicit scopes,
epi_week, label_phone and support_contact. Its scope is a display projection;
action/object checks use the original paired grants. A logo_url is an API path,
never a storage URL. No approved asset means null/initials. **[ASSUMPTION]** The
no-dependency fallback accepts only validated <=1 MiB, <=1024x1024 noninterlaced
8-bit RGB/RGBA PNG, strips metadata and rejects invalid magic/CRC/pixel streams.
Other image formats need a verified sanitizer integration before acceptance.

Catalog item projections add `protected`, integer `usage_count`, compatible
`in_use = usage_count > 0`, `created_by` / `created_by_username` and nullable
`deactivated_at` / `deactivated_by` / `deactivated_by_username`. Counts sum existing
organization-scoped historical references; seed authors are null. Activation
clears deactivation metadata. Protected Other cannot be
edited (409 other_item_protected) or deactivated (existing #3 code); it remains
last. Deactivated items remain in admin reads with their labels and references.
OP01's nine catalogs coexist with #80's void-reason catalog (decision 91 supersedes
OP15); void validation is unchanged. The 13 versioned launch rules have the
OP03/OP04/MO02-MO04 bounds/defaults documented in rules/README.md. Fuel min must
remain below max through scheduled transitions (400 fuel_bounds_conflict).
R02/R03 retain organization-only rules, no backdating, historical evaluation and
ETag/next_change_at refresh. No new sync events or result codes are added.


## Geography editor (#108, B-11)

All routes are under /api/v1. Organization is derived from membership, including
pinned bearer device authentication; the web retains session cookie plus CSRF.
No organization URL/body selector, risk color or permit authority is introduced.

- GET/POST /quadrants/; GET /quadrants/{id}/. Creation takes {center,code,geometry}
  and creates immutable identity plus revision 1. GET/POST /quadrants/{id}/versions/;
  POST takes {geometry,expected_revision,point_resolutions?:[{point,decision,evidence,location?}]}.
  Returns 201 {version,spacing_warnings}. The first publication of a platform-created
  unversioned identity expects revision 0; HTTP-created identities start at 1.
- GET/POST /blocks/; GET /blocks/{id}/. Creation takes {quadrant,code,geometry}.
  GET/POST /blocks/{id}/versions/ append block polygons with {geometry,expected_revision}.
  Blocks must initially fit the quadrant; a new block polygon cannot exclude active
  points (409 unresolved_points). Existing block history survives a quadrant edit.
- GET/POST /sampling-points/; GET /sampling-points/{id}/. Creation takes
  {block,code,location:[lon,lat]}; GET/POST /sampling-points/{id}/versions/ relocates
  with {expected_revision,location}. Writes return 201 {point,spacing_warnings}.
  Point code and block never change; retired identities keep reserving their code.
- GET /blocks/suggestion/?quadrant=<uuid> returns proposals with geometry, four
  distinct interior points and requires_review=true; existing blocks are subtracted. Read-only; nothing is published.

Lists/history use page-number paging; coded identities support exact scoped ?code=,
search and ordering=code|created_at (descending with -). Quadrants filter center;
blocks filter quadrant; sampling points filter quadrant/block. Foreign or ungranted
filter references return 404, just like unknown references. Identity list/detail
?captured_at=<ISO instant> projects the version active at capture (null before the
first publication). The temporal selectors also resolve block and point history;
latest current version is the highest revision, never an in-place overwrite.

quadrant.read authorizes reads/suggestions; quadrant.publish creates quadrants,
blocks and publishes polygons; sampling_point.create creates/relocates points.
Admin/coordinator receive all three once; supervisor read only. Every applicable
permission AND center AND quadrant must be covered by one existing effective
profile/membership grant. Foreign organization/center/quadrant/block/point returns
404 without disclosing existence; absent action codes default to 403. Scope creation
requires an explicit quadrant all grant because a new UUID cannot be preselected.

Polygon only, coordinates [lon,lat], finite WGS84 bounds, closed rings, valid holes;
MultiPolygon/other types, self intersections and antimeridian-crossing polygons
are 400 validation_error with fields.geometry/invalid_geometry. Boundary is inside.
All outside active points need exactly one evidenced keep/move/remove decision.
Move must enter the proposed quadrant; keep explicitly accepts an outside location;
remove appends retirement, never deletes. Missing decisions return 409
unresolved_points with safe blocked_by point ids from the authorized quadrant.
Extra/duplicate decisions return 400 invalid_resolution_set; foreign points are 404.
Every later polygon edit must resolve still-outside kept points again.

Organization NO KEY UPDATE precedes Quadrant locks; authorization and revision are
re-read inside that transaction. A stale expected_revision returns 409 stale_revision
with safe blocked_by. Simultaneous valid publications serialize to one successor and
one 409. Database lock timeout/deadlock is retryable 429 geography_in_progress with
Retry-After: 1. No User/Device/Session/Token locks or external IO are taken below it.

Spacing reads rules.selectors at check time: min_distance_same_block_m, default 50,
bounds 10..200 metres. Distances strictly below it return spacing_below_minimum
warnings ({point,distance_m,minimum_m}); equality after micrometre rounding is allowed. Haversine uses mean
Earth radius 6371008.8 m, <=0.6% ellipsoid error. Keep/move publication also reports
spacing warnings. No sync events/result codes change, so docs/sync.md and sync i18n
remain unchanged. Error envelopes keep code/detail, fields only on 400 and safe
blocked_by on 409. See geography/README.md for choices and acceptance mapping.

separate from source-event void status. Replacement capture provenance replaces
placement provenance for a new identity; supply_refs is empty (no inventory exists).

GET /api/v1/relocations/ requires relocation.read and page-number paging. Filters:
code=<proposal UUID>, status=pending|approved|rejected, point=<sampling point UUID>,
ovitrap=<physical UUID>, include_voided=true (default false). Ordering fields are
created_at, event__device_time, ovitrap__sampling_point__code (optional minus);
default -created_at,id. Status derives from appended decisions; B-33 owns their
writer. A proposal never changes approved geometry. Void metadata remains distinct
from decision status; voided proposals are excluded from the default pending queue.

GET /api/v1/ovitraps/{physical UUID}/history/ requires ovitrap.read. It returns the
fixed point code, computed suggest_relocation and chronological lifecycle sources
across physical identities: source event UUID, both timestamps, author, ingest/void
state and void-event reference, original payload/GPS/tokens and applied lifecycle
provenance. Ordinary checks and bags remain behind reading.read and are excluded.
Reading projections expose incident_link for abandoned/removed findings; removal
history exposes the same marker and recovery_state. The marker is an opaque unique
append-only identity for future B-06, not a verified incidents-app FK.

Both endpoints default-deny and enforce organization AND paired center/quadrant
scope; foreign point/ovitrap filters and history references return 404. Organization
comes from membership/session, never URL/body. Web cookie+CSRF and pinned device
bearer policies are inherited. relocation.read is granted once to seeded admin,
supervisor and coordinator; later revocations/custom profiles remain unchanged.
Only GET routes are added; sync state conflicts use per-event codes/safe blocked_by,
not a new HTTP correction route. HTTP validation keeps code/detail/fields (400).

OP03 uses the existing versioned 2 weeks (1..8) / 3 incidents (1..10), counting local
epi weeks and fixed-point incident markers. Suggestions are advisory. Voids require
normalized 10..1000 visible-character text and preserve lifecycle/decision dependents.
No stock compensation exists in this baseline. Quadrant closure writers remain
follow-ups. ADR 120 and backend/ovitraps/lifecycle/
README.md document SQL guards, lock order and the acceptance map.

## Unrecovered removal resolution (#217)

POST /api/v1/ovitrap-removals/{removal UUID}/resolve/ requires removal.resolve.
The UUID is the removal_id retained in physical history, never a physical-trap
UUID or organization selector. Request: {expected_state,outcome,reason}.
expected_state is explicit: unrecovered|recovered|resolved|voided; only a still
unrecovered, unvoided accepted source with no existing resolution can resolve.
Any different expectation, recovered/voided source or double resolution returns
409 removal_state_conflict with no new row. Outcome is recovered_later|written_off;
both require the existing normalized reason minimum (default 10 visible characters,
maximum 1000). No new catalog: archived source choices/labels remain evidence and
may be inactive when the supervisor records the independent resolution.

201 returns {id,removal,outcome,reason,created_by,created_at}. The one-to-one
insert-only row is the audit fact; the original removal/event/incident marker is
untouched. Existing physical history adds effects.resolution (null or the audit
fields); recovery_state remains the original capture's state. Only the resolved
removal stops contributing to has_unresolved_removal. Another unrecovered removal
at the same point still blocks. Actual quadrant closure remains an external B-33
follow-up; no closure or incident endpoint is introduced.

Permission is granted once to seeded admin/supervisor; custom profiles and revoked
grants are retained. Organization AND paired center/quadrant scope apply before
lookup/locking (foreign or out-of-scope=404). State and scope are rechecked inside
the transaction. Source FieldEvent NOWAIT NO KEY UPDATE precedes Organization
NOWAIT NO KEY UPDATE, matching generic void's inherited order; no later account
locks or external I/O. Contention/deferred-FK lock waits/deadlocks roll back and
return 429 removal_in_progress, Retry-After: 1. Resolution is a retained dependent:
later source void uses existing ovitrap_void_blocked with a safe resolution ID.
No new sync event, result code or courier payload is added. See accepted ADR 130.
