# API conventions (mobile + web)

Single contract for every client. Source of truth: OpenAPI schema generated by drf-spectacular; `packages/api-client` is generated from it (`npm run api:generate`), and CI fails a PR whose committed schema or client is stale.

| Topic | Convention | Status |
|---|---|---|
| Base path | `/api/v1/`. Field-only endpoints under `/api/v1/field/` (sync, catalog snapshot, rules snapshot, uploads). | Accepted |
| Naming | Plural kebab-case English nouns; actions as `POST /<resource>/{id}/<verb>/`. | Accepted |
| Organization | Resolved from the authenticated user's membership. Any `organization_id` in the body is ignored. Objects of another org → `404`. | Accepted |
| Multi-org users | Active org chosen with header `X-Organization: <slug>`; required only if the user has more than one active membership (else `400 organization_header_required`). A slug that is not one of the user's active memberships is always `403 no_active_membership`, even for users with one membership. Active = membership and organization both `is_active`. | Accepted |
| No delete | No `DELETE` on business data. `POST …/void/` with `{reason}`; responses carry `voided_at`, `voided_by`, `void_reason`; lists exclude voided unless `?include_voided=true`. `PUT`/`PATCH` on a voided record → `409 already_voided`. Mobile uses a void event in the sync batch with the same semantics. | Accepted |
| Blocked actions | `409` + `{ "blocked_by": [{ "reason", "unblocked_by_role", "link" }] }`. | Accepted |
| Errors | Every 4xx/5xx body: `{ "code": "<machine_code>", "detail": "<English, for logs>", "fields": { "<field>": [{ "code": "<machine_code>", "params": {} }] } }`. `fields` only on `400`. Clients show text from `packages/i18n` by `code`; `detail` is never shown to users. `409` blocked actions add `blocked_by` (see above). | Accepted |
| OpenAPI contract | `packages/api-client/openapi.yaml` is the committed export (dev settings, `--validate --fail-on-warn`). The `ErrorEnvelope` component (`code`, `detail`, optional `fields` and `blocked_by`) is the `default` response of every operation, so clients type every non-2xx body as the envelope. Page-number lists declare `Paginated<Name>List` with `count`; cursor lists declare the same name without `count` (give a cursor list its own serializer class so the component names do not collide). Any API change in a PR also commits the output of `npm run api:generate`. A change that breaks existing clients (removed or renamed path, field or parameter, a field that becomes required, a narrower type) is marked in the PR template checkbox "API breaking change". | Accepted |
| Paging | Page number (`?page=&page_size=`, response `{count, next, previous, results}`) for admin tables. Cursor (`?cursor=`, response `{next, previous, results}`) for large or streaming lists: sync changes, access log, notifications, field events. Each endpoint declares one style in OpenAPI. | Accepted |
| Objects by code | Human codes (OV-010, B-4471, C-07, I-0236) resolvable via `?code=` on the list endpoint (returns 0 or 1 result). Detail routes use ids. Implemented by `core.filters.CodeLookupFilter`: a viewset opts in with `code_lookup_field = "code"`; exact match (case-sensitive) after trimming surrounding whitespace, only on the `list` action, scoped to the active organization like any list; a repeated `?code=` uses the last value; a blank value, one longer than 50 characters or one with NUL characters is `400 validation_error` with `fields.code` (`blank`, `max_length`, `null_characters_not_allowed`). The filter is registered in `DEFAULT_FILTER_BACKENDS`; a viewset that sets its own `filter_backends` must keep it. The "0 or 1 result" guarantee requires `UniqueConstraint(organization, code)` on the model (the code is unique per organization, not globally). Documented per operation in OpenAPI. | Accepted |
| Exports | `GET …/export/?format=csv|pdf`, server-side, logged in access log; personal data blank without transfer authorization. | Accepted |
| Rules | Per-key parameters with versions and `effective_from`; never overwritten. Mobile downloads a snapshot with a `rules_version` hash. | Accepted |
| Catalogs | `/catalogs/{slug}/items/`; "Other (specify)" item is fixed and cannot be deactivated (`409`). | Accepted |
| Auth | Mobile: token (access + refresh) bound to a registered device. Web: Django session cookie + CSRF token (`SameSite=Lax`, `Secure`, `HttpOnly`). Same user model and permissions. | Accepted |
| Live data | Django Channels WebSocket for live shift positions. Path and auth defined in #19. | Pending (#19) |
| User-facing text | The API never returns user-facing text. It returns `code` + `params`; mobile and web translate with `packages/i18n`. Exception: catalog item labels configured per organization (`label_es`, `label_en`) are data. | Accepted |
| Time | All timestamps ISO 8601 UTC; organization timezone and epi week from `/me/`. Field events keep `device_time` + `server_received_at`. | Accepted |
| `GET /me/` | `{ user: {id, username, email, first_name, last_name}, organization: {id, slug, name, country, timezone, languages[], logo_url} \| null, profiles: [{slug, label_es, label_en}], permissions: ["<resource>.<action>"] (sorted, unique, union of active profiles), scope: {centers: [], quadrants: []}, organizations: [{slug, name}] }`. Exempt from the multi-membership `400`: with several memberships and no header, `organization` is `null`, `profiles`/`permissions` are empty and `organizations` lists the choices. No active membership → `403 no_active_membership`. Epi week is added when its rule exists. | Accepted |
| `GET /health/` | `{"status": "ok"}`; no authentication, no organization, no throttling. | Accepted |
| Error codes (#2) | `validation_error` (400, with `fields`), `parse_error` (400), `organization_header_required` (400), `profile_organization_mismatch` (400), `not_authenticated` (401), `permission_denied` (403), `no_active_membership` (403), `not_found` (404), `method_not_allowed` (405), `already_voided` (409), `throttled` (429, with `Retry-After`), `server_error` (500). Field error `params` is `{}` until a rule needs parameters. Unauthenticated requests are `401` (session auth sends `WWW-Authenticate: Session`). | Accepted |
| OPTIONS | Denied (`403`) on scoped resources: there is no permission code for `metadata`, so serializer metadata is not exposed. | Accepted |
| Permissions | A profile holds permission codes `<resource>.<action>`; a view declares `required_permissions` (action → code) and DRF `HasPermissionCode` checks the code of the current action against the union of the user's active profiles in the active organization. | Accepted |
| Field snapshots (#3) | `GET /field/catalog/` and `GET /field/rules/` return the whole configuration in one compact body with a `version` (SHA-256 of the canonical JSON of the content). The same value is the `ETag` (`"<version>"`); `Cache-Control: private, no-cache`; `Vary: X-Organization` (the answer depends on the active organization). A matching `If-None-Match` (weak `W/` prefix and `*` accepted) gets `304` with no body, after authentication and permissions are checked. Catalog snapshot: `{version, catalogs: [{slug, label_es, label_en, is_open, items: [{id, code, label_es, label_en, icon, sort, is_other, requires_photo}]}]}`, active items only, "Other" last; a blank `label_en` means "use `label_es`". Rules snapshot: `{version, next_change_at, parameters: [{key, value_type, unit, value, effective_from, version_id}]}`; `value` is a JSON number, or `null` when the parameter has no value yet ("not configured"); versions scheduled for later and voided versions are left out, and the earliest scheduled one is `next_change_at` (it is part of the hash). The `version` is a consistency token: the values that applied at a past instant come from the version history, not from the hash. Mobile refreshes when sync reports a new `catalog_version` / `rules_version` (#5), on login (`If-None-Match`) and when `next_change_at` passes. | Accepted |
| Rule parameters (#3) | `GET /rule-parameters/` and `GET /rule-parameters/{key}/` (lookup by key): `{key, value_type: integer\|decimal, unit: m\|km_h\|s\|min\|week\|count\|km_l, min_value, max_value, value, effective_from, version_id, next_change_at}`. `GET /rule-parameters/{key}/versions/` is the full history (voided versions included), newest first, and `GET .../versions/{id}/` one version; each is `{id, value, effective_from, effective_date, reason, status: scheduled\|in_force\|superseded\|voided, created_by, created_at, voided_at, voided_by, void_reason}`. `POST .../versions/` takes `{value, effective_from, reason}` where `effective_from` is a local calendar date (`YYYY-MM-DD`): today takes effect immediately (several versions for today are allowed; the latest `effective_from` wins, so a seeded value can be corrected on day one), a future date at 00:00 in the organization's timezone (at most 365 days ahead, one non-voided version per date), a past date is rejected. `POST .../versions/{id}/void/ {reason}` voids a version that has not taken effect yet (`409 version_not_scheduled` otherwise, `409 already_voided` twice): it stays in the history, leaves the value in force and the snapshots, and frees its date. There is no `PUT`, `PATCH` or `DELETE` on versions (`405`); parameters are created by the seed, so there is no `POST` on `/rule-parameters/`. Parameters are per organization (no regional override). | Accepted |
| Catalog items (#3) | `GET /catalogs/` lists the catalogs (created by the seed, no `POST`). `GET/POST /catalogs/{slug}/items/`, `GET/PATCH /catalogs/{slug}/items/{id}/`; no `PUT` or `DELETE`. `POST` takes `{code, label_es, label_en?, icon?, sort?, requires_photo?}`: `code` is lowercase (`^[a-z0-9][a-z0-9_-]*$`, max 64) and `other` is reserved for the fixed "Other" item; `icon` is `^[a-z0-9-]+$` (max 64); `sort` is 0 to 10000, and an omitted `sort` appends the item before "Other". `PATCH` edits labels, icon, `sort` (this is the reorder contract) and `requires_photo`; `code`, `is_other` and `is_active` are ignored. `POST …/deactivate/` and `POST …/activate/` are idempotent. A catalog holds at most 200 active items. A catalog slug or item of another organization is `404`. | Accepted |
| Error codes (#3) | Field errors (`400 validation_error`, `fields`): `duplicate_code` and `reserved_code` (item `code`), `sort_exhausted` (item `sort`), `effective_from_in_past`, `effective_from_too_far` and `duplicate_effective_date` (version `effective_from`), `not_an_integer` and `out_of_range` (version `value`; `out_of_range` params are `{min, max}`, `null` when unbounded). Plus `409 other_item_cannot_be_deactivated`, `409 catalog_item_limit_reached` and `409 version_not_scheduled`. Services raise `core.exceptions.FieldValidationError` to report a coded field error with `params`. | Accepted |
| Permission codes (#3) | `catalog.read`, `catalog_item.create`, `catalog_item.update`, `catalog_item.deactivate`, `catalog_item.activate`, `rule_parameter.read` (parameter list and snapshot), `rule_parameter_version.read` (history), `rule_parameter_version.create`, `rule_parameter_version.void`. Seeded once per profile created by the seed: `admin` all; `courier`, `supervisor`, `entomologist`, `community_promoter` `catalog.read` and `rule_parameter.read` (the field snapshots need them). Admin lists of items also run under `catalog.read`. | Accepted |
