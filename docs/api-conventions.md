# API conventions (mobile + web)

## UIEB shipment source and material delivery (#118)

`GET/POST /uieb-shipments/` and `GET /uieb-shipments/{id}/` expose the versioned
`source-projection-v1` described in [shipments](../backend/lab/shipments/README.md).
Creation takes `{source_ids, cutoff, recipient_institution?, supersedes_id?, reason?}`;
correction appends a linked shipment with a normalized reason, preserving the old
snapshot/hash. A voided source or later lot version flags supersession. This is
source data only; B25 owns the authoritative template, PDF and preview mechanics.
Current B24 eligibility is checked on every response. RFC is blank with an omission
code even when eligible until the protected #100 source exists; no RFC is stored
in the snapshot or general cache.

Material requests use `GET/POST /material-requests/`, detail reads and
`POST /{id}/cenaprece-notification/ {reference,date,evidence_ids}` then
`POST /{id}/deliver/ {command_id,signature_upload_id,expected_revision}`. Creation
takes `{recipient_institution,lot_id,location_id,piece_id?,quantity,unit_version_id?}`
and pins a genuine positive custody unit at the real location; an unambiguous unit
is selected automatically. Every notification upload increments revision; delivery/void
each increments it. Notification proof and delivery signature must be separate
verified owned/device-matching uploads. The canonical private parent is
`material_request`; downloads recheck `material_request.read`. Exact authorized
delivery retries return the original receipt without a second debit. Missing
notification/evidence, stale revision, changed command or unsafe stock returns
the existing coded409 envelope with safe `blocked_by`; contention is retryable429.

Read/create/void actions use `shipment.*` or `material_request.*`; notification is
`material_request.notify`, delivery is `material_request.deliver`. Complete actual
scope vectors are authorized before list count/page and again beneath the shared
Organization arbiter on writes. Lists support scoped exact code, center/quadrant,
created_at/code ordering and `include_voided`. Open resources accept
`POST /{id}/void/ {reason}` with normalized10-visible/1000-stored text; delivered
requests return409 until genuine compensation exists. These HTTP commands add no
FieldEvent, sync result code, queue or history producer. No sync status is changed.

Single contract for every client. Source of truth: OpenAPI schema generated by drf-spectacular; `packages/api-client` is generated from it (`npm run api:generate`), and CI fails a PR whose committed schema or client is stale.

## Regulatory permits and releases (#116 / B-20)

All routes below use `/api/v1/`. Organization comes from the authenticated
membership/device session. Every object action checks its current permission and
actual center/quadrant pair; missing actions deny, and foreign references are
indistinguishable from absent ones. Web commands retain session-cookie/CSRF checks;
field sync retains pinned bearer-device authentication.

| Method/path | Contract |
| --- | --- |
| GET/POST permit-types/ | `permit.manage`; creation requires one explicit organization-wide grant. Body: code, name, requirements containing exactly positive finite max_gps_accuracy_m. Immutable type identity is the requirements pin; no threshold is seeded. |
| GET/POST permits/ | `permit.manage`. Creation: code, quadrant, type, number, authority, official_document, document_attestation, geometry, valid_from, valid_to. Center derives from the actual quadrant. |
| GET permits/{id}/ | `permit.manage`; identity, revision, current version, suspension and coded blocked_by. |
| POST permits/{id}/versions/ | `permit.manage` and `field.upload` on the pair. Complete version body without code/quadrant, plus expected_revision. Appends history. |
| POST permits/{id}/suspend/ | `permit.suspend`; reason and expected_revision. Appends permanent suspension, author and server time for this permit identity. |
| POST permits/{id}/schedule/ | Current `schedule.manage` and `permit.manage` on the pair; courier needs paired sync and bootstrap grants. Takes point_id, courier_id, due_date, expected_revision. Returns task_id, permit_version_id, due_date and courier_id. |
| GET/POST release-devices/ | Read requires `release.read`; create requires paired `permit.manage`. Body: code, quadrant, source_lot. Returns immutable biological source lot/version and initial active status. |
| GET release-devices/{id}/ | `release.read`; source lineage and coded blocked_by. |
| POST release-devices/{id}/status/ | Paired `permit.manage`; status=active/inactive/retired, reason, expected_revision. Appends an authored status revision; retirement is terminal. |
| GET releases/ and releases/{id}/ | `release.read`; original source UUID, permit/device/lot/training/task pins, physical quantity, GPS, both clocks and safety/stock provenance. |

Permit/device/release lists use page-number paging, server ordering and
center/quadrant filters. Coded resources support scoped exact `?code=`; types and
permits/devices also expose their declared search/order fields in OpenAPI.
Permit validity is aware `[valid_from, valid_to)`. Reasons and document attestations
normalize to at least ten visible characters and at most 1000 stored characters.
Structural errors use400 fields; state/revision conflicts use409 safe blocked_by;
NOWAIT contention returns429 with Retry-After. No PATCH or DELETE is provided.

`official_document` input is the actor's own verified unbound public upload UUID;
the version retains the actual UploadVerification identity and authored review
attestation. Current `field.upload` is independently required (#343). The upload must
be `application/pdf`, `image/jpeg` or `image/png` (scans); any other type is rejected with 400
`permit.document_type_invalid` on `official_document_id`. One upload backs at most one
permit version: reuse is 409 `permit_document_already_bound` (unique constraint as
backstop). **[ASSUMPTION]** the authorized reviewer attests that this verified document
is an official signed/reviewed permit and that its polygon matches it. **[DECISION #343]**
PDF, JPEG and PNG are all accepted because the generic `uploads` app only accepts images
today (real PDF support in `uploads` is a separate follow-up; decision 171 already covers
the review attestation). The verifier does not authenticate a digital
signature. Release `provenance` exposes regulatory ids only (permit version, type,
document, lot version, schedule task, transit policy/mode, quantity), never courier,
certification, reviewer, assignment or receipt ids. Retained
verification grants no attachment download or reparenting capability. Risk colors
and courier-drawn polygons never grant regulatory authority.

Release tasks are explicitly created through the permit action and bind the real
permit version, sampling point, local due date and courier ownership. The general
planner still derives only place/check tasks from risk/work history. An active
release device, a risk label or a downloaded permit does not authorize a release.
Device reads expose the latest status and revision; status CAS preserves the
original equipment/lot identity. Inactive or retired equipment blocks ingestion
and later acceptance. Task, permit-version binding and capture-time owner must
already exist at device_time; current ownership must still match. Capture training
uses only requirements, training and certification facts recorded by device_time,
then independently checks current qualification. Later backdated facts cannot
create capture authority. Review retains the exact original task/binding/owner pins.
The existing assignments producer advances3 to4 to include action=release and its
real completion state; the new permits producer is1. Root2/history7/supplies1
remain unchanged. Older cursors require bootstrap recovery at the producer boundary.

`release.record` rechecks capture-time and current permit validity/official zone,
training, explicit task ownership, GPS quality, verified evidence and genuine
courier lot custody. Invalid safety cannot be supervisor-approved. The existing
manual_evidence_review transit policy can retain a source for authorized review;
that acknowledgement preserves the exact original receipt/policy/evidence and
revalidates every mandatory gate before one Release and its canonical stock debit.
New in_review sources have no operational effects. See
[the sync contract](sync.md#revalidated-releases-116--b-20) for result codes.

Suspension publishes a scoped permits feed upsert in the same transaction and
retains recipient-specific PermitSuspensionNotice facts for eligible courier/
coordinator memberships. Their delivery_unavailable status records absent external
transport, not a delivered notification. Source and effect/receipt history remain
separate; physical consumption is retained when a void is refused.

## Training eligibility and private evaluations (#101)

B03 adds `/trainings/`, `/trainings/{id}/versions/`, `/training-requirements/`,
`/training-requirements/{action}/versions/`, `/users/{id}/trainings/` and its
`/{certification_id}/revoke/` command. Training/rubric identity/version writes
require explicit organization-wide training.manage. Personal facts and requirements
use their real center/applicable-quadrant pair. Versions explicitly configure
positive validity and enabled action keys; certifications pin verified image
evidence, issuer/reference/attestation and aware `[valid_from,valid_to)`.
Backdated facts retain recorded_at and cannot prove an earlier publication.
An accepted future TrainingVersion cannot qualify before its effective_from.

`/evaluation-rubrics/` and `/{id}/versions/` publish exact immutable rubrics.
`POST /evaluations/` records full observation objects, with null for missing
sections/checks. Technical defaults20/50/30 and pass>=80 use Decimal/unrounded
comparison; missing answers mean incomplete, and a critical failure cannot pass.
No scientific checklist/validity is seeded. Private evaluation.read remains
independent of evaluation.create. Every write takes command_id/expected_revision;
exact retry reauthorizes saved subjects and returns its original receipt before
fresh CAS/state, while changed target/body conflicts. Evaluation `/revisions/`
takes a complete successor observation plus expected_completion_sequence and
canonical reason_code/reason; `/void/` uses the same frames/reason. Keep the original
rubric/person/context and observations. Reasons normalize to ten visible minimum
and1000 stored maximum. Server completion sequence, not observed_at, orders results.
Incomplete neither increments nor resets; completed pass resets; low/critical_failure
is adverse. The2->3 transition retains one episode cause without fourth-result
duplication or fictional delivered recall.
Unknown critical response keys return 400 validation_error with
fields.critical_responses code unknown_check. Invalid calendar instants return
the field's invalid code; valid instants without a zone return naive_datetime.
Revision/void reconciles the resulting effective episode: removing an intervening
pass can discover the actual third adverse completion, with its original author
and a truthful current cause/publication time.

`GET /evaluation-notice-policy/` and `POST /evaluation-notice-policy/versions/`
use a real context/explicit active recipient_membership_id. Current training.manage
AND evaluation.read must each cover the whole actual vector in one contributing
pair. Optional bounded unique reroute_cause_ids atomically redirects only current
pending causes with proven nonpublication. Recheck the actual episode even before
deferred reassessment; superseded/published/ambiguous causes conflict and roll back
policy+routes. Ordinary policy edits never redirect history. Missing/revoked HR
routing remains unavailable; expiry uses the active subject/actual valid_to.
Owned durable causes/intents/attempts are not delivery or Incident records.
Publication/reroute uses the captured contexts plus the entire current episode's
actual contexts. A fourth adverse result adds facts and scope without another
trigger; an incomplete retained policy vector remains recipient_unconfigured
with no attached intent. Each publication frame records status, facts, policies,
recipient_membership_id and that complete context vector.

`GET /users/{id}/trainings/` returns operational training.read summaries; proof
requires training.manage. Its `/{certification_id}/revocations/` pages immutable
private history, with wrong subject/certificate opaque404. `GET /evaluations/{id}/attempts/`
pages original/successor observations under current evaluation.read, including
corrected/voided cases. Current evaluations include the actual void receipt/reason/
author. Whole context scope precedes filter/count/page. No directory, private
evaluation or proof-byte authority follows from training.read.
Evaluation lists accept center/quadrant, subject and include_voided. Certification
lists accept center/quadrant, training_version and proof; requirement and notice
policy lists accept center/quadrant. Known filters from another route return a
typed unsupported_filter400 and are absent from that route's OpenAPI parameters.

`GET /users/{id}/eligibility/?action=&center=&quadrant=&at=` is factual qualification
under current training.read. Retrospective/future queries never mint capture proof
or release permission. Genuine self DeviceBearer bootstrap/changes can publish
typed eligibility after current field.bootstrap AND field_event.sync on its real
pair and prepared account/Org/courier arbitration. Minimal version pins, coded
blockers, validity boundaries and opaque assessment receipts expose no scores/HR/
evidence. Cookie/forced/unbound and no-pull/final uploads mint no receipts. Semantic
expiry refreshes actual projection/feed and earliest next_change_at before304,
without request-clock/token-only hash churn. Historical pair UUIDs are scalar;
token pruning and Session.user dissociation do not erase business provenance.

Certification is one additional concrete B04 parent. Stage/PUT/finalize unbound
verified bytes outside locks, then consume the exact owned declaration with current
training.manage+field.upload for its actual context, committing Certification/
attachment/command atomically. Current training.manage independently authorizes
download before/after unlocked I/O. Existing parents, CSRF, authentication, error
envelopes and government clamps remain authoritative.

## Reported incident workspace reads (#304)

The single `incidents/` facade still defaults to fleet; only explicit
`kind=reported` selects reported list filtering/order. New collection fields are
`assigned_to_me`, `overdue`, `escalated` (lowercase true/false only), `type` (stable
CatalogItem UUID; existing type_id remains an immutable version UUID) and `origin`
(field_event/direct_report/review_decision/inventory_condition/lab_reception/unknown).
Membership identity and one server query time drive audience/deadline predicates.
Overdue=open with nonnull deadline<=now; escalated=open stage>0 independently of
latest comment or null terminal deadline. False complements each predicate;
filters intersect. Origin is one coherent persisted creation-proof classifier
shared by filtering/count/projection before pagination; unsupported/conflicting
proof is unknown and later marker adoption never rewrites creation cause.

Reported ordering strictly accepts comma-separated code,created_at,deadline,severity,
optional minus, always preceded by critical rank and followed by id. Severity is
enum order rather than lexical; default deadline asc/null last,created_at,id.
The existing page count is authoritative for those same scope/predicates; independent
count requests are not an atomic multi-counter snapshot. Detail/actions ignore
collection predicates. Fleet's old order/facets/296 clearance remain exact, and
reported continues ignoring unsupported motorcycle input, even malformed values.

Reported snapshots add stage, nullable owner_display and event author_display,
exact archived type_snapshot, origin, linked_record, blockers, evidence,
action_permissions and nullable action_prerequisites. A closed linked_record has
kind/available/id/code/is_voided; unavailable references redact identity/code/void
state, not the readable incident. No web href or human code is invented. Evidence
retains the public audit UUID and nullable is_verified/verified_at/content_type/
size_bytes plus current is_readable from the REAL immutable bound parent. This
metadata reads no blobs and grants no bytes, uploads, reparenting or command
evidence admission. All six parent ACLs remain authoritative, including exact
Lab-rejection read OR void, full review and transfer vectors. New private fields
fail closed without current incident.read for the case pair; create-only callers
retain the old write contract without gaining private read projections.

Action booleans use existing comment/create, reassign/change_severity and close/void
codes on their whole current pair. Separate prerequisites expose state/dependents,
protected severity, immutable close minimum and current field.upload capability;
they never replace the writer's current CAS, policy or exact evidence checks.

New GET `incidents/context-options/` requires action=read|create, optional center
UUID/search/page/page_size, and returns named authorized center/quadrant pairs,
including explicit null-quadrant center-only options. GET
`incidents/{id}/owner-options/` requires incident.read plus incident.reassign for
that case pair, accepts search/page/page_size, and returns membership_id + label.
No center.read/role.read/global-directory grant is added. Complete current scope,
activity/government and terminal eligibility precede search/count/page; writes
revalidate. Unknown/foreign/out-of-scope selected targets are opaque404; malformed
known parameters/unsupported ordering are typed400. Other default-denied metadata
and authentication behavior remain unchanged.

Existing GET incident-types gains opt-in reportable=true: latest family version
AND parent item must be active; false/omission keeps existing visibility. Old
version is_active meaning, submitted active pins, archived close policy and all
type-management/incident writer bodies are unchanged. No summary endpoint, new
model/job/permission, Lab writer, upload parent or history producer is introduced.

## Exact movement lot-code filtering (#292)

Existing `GET /api/v1/locations/{id}/movements/` accepts optional `lot_code`, an
exact human code validated through public CodeQuerySerializer: trim surrounding
whitespace, maximum 50 characters, nonblank and no NUL. Invalid values return
`400 validation_error` with `fields.lot_code`; generic code grammar is unchanged.
Repeated input uses its last value. A UUID-looking value under `lot_code` remains
a code; the existing `lot` field remains a UUID. There is no substring, case-fold,
wildcard, comma-list or code-to-UUID resolver behavior.

Current parent location authorization precedes reference disclosure. The code,
like an existing lot UUID reference, must have a historical leg visible through
current same-tenant paired `location.read` and `lot.read` scope. Unknown, foreign
and wholly hidden references share safe 404. A reference readable at another
authorized location may yield an empty page here. `lot` and `lot_code`, when both
declared, intersect with AND after their existing reference checks; contradictory
readable values yield an empty page. No original-admission/current-lot lookup or
positive-balance requirement is added.

All predicates apply to the requested location's permitted historical queryset
before count/order/page. Existing supply/operation/piece/unit/time filters,
default ordering, stable ties, pagination and Movement response remain exact.
This filter works after B's stock reaches zero without granting current B lot
metadata or private A/C transfer details. Transfer redaction still requires its
whole vector. No stock, lot list/detail, condition or PATCH parameter is added;
absent `lot_code` preserves existing behavior. The optional detail
`custody_location` UUID query delivered by #106 remains separate.

## Private evidence (#102)

POST /api/v1/field/uploads/ accepts {content_type,size_bytes,sha256}, with optional
client_id (immutable offline evidence UUID) and context {kind: field_event or
motorcycle_fault,id}. The three-field API stages private UNBOUND bytes and confers
no resource access. Known field-event context requires client_id and the exact
declared UUID/author/device. The response is 201
{upload_id,url,method:PUT,headers,expires_at}. url is a relative local API endpoint,
not a public storage URL. Authentication remains required on PUT. Upload-Lease is
a signed, latest-revision ticket valid for 15 minutes; send it and the returned
Content-Type with raw bytes to PUT /field/uploads/{id}/content/ (204).

POST /field/uploads/{id}/renew/ returns 200 {id,state,verified_at} plus the new
authorization fields, retaining upload_id. POST /field/uploads/{id}/finalize/
accepts optional context and returns 200 {id,state,verified_at}; repeated success
returns the same immutable verification fact. States derive from facts:
authorized, received, verified. A received source may finalize after lease expiry.
GET /attachments/{id}/download/ uses that same public upload UUID, requires a
verified single authorized parent binding, rechecks CURRENT parent read/history
scope before/after unlocked file I/O, and returns sanitized bytes with
Cache-Control: private, no-store and X-Content-Type-Options: nosniff. No raw key,
source bytes or durable download capability is exposed. Voided history remains
available under its real parent read policy; revoked/out-of-scope access does not.

Action field.upload is required for authorize/renew/PUT/finalize, plus fresh owner
and device identity. Binding applies current parent action AND center AND applicable
quadrant without combining profile grants. Current parent read authority governs
download, including readers without field.upload. Foreign/unknown references are
404 before the Upload arbiter. Cookie/CSRF and pinned bearer policies are unchanged.
Seeded admin/supervisor/courier receive field.upload once; custom/revoked grants
stay unchanged. These byte endpoints do not accept revoked final-sync entitlement;
retain local files and reauthenticate/re-authorize without recapture (#246).

JPEG/PNG only, <=10 MiB original/sanitized bytes, <=25 MP and one frame. Actual
size/type/original SHA-256 are verified before Pillow metadata removal. Original
and sanitized hashes remain separate. 400 validation_error fields.file codes:
upload_incomplete, upload_too_large (max_bytes), upload_hash_mismatch,
upload_type_mismatch, upload_invalid_image, upload_pixel_limit (max),
upload_animation_not_supported, upload_sanitized_too_large (max_bytes).
Metadata serializer fields use existing required/invalid/invalid_choice/min_value/
max_value codes. 409 codes with safe blocked_by code entries:
upload_identity_conflict, upload_already_bound, upload_lease_invalid,
upload_lease_expired, upload_incomplete. 429 upload_in_progress carries Retry-After:1;
503 upload_storage_unavailable preserves retryability. Fleet adds HTTP-only 409
motorcycle_evidence_not_ready using its existing safe blocked_by shape.

clear_fault now checks verification/binding to its exact fault before effects.
Ovitrap lifecycle and archived requires_photo checks use existing
ovitrap_evidence_required in_review. Check accepts optional evidence_ids default [].
Post-_store linkage preserves pending references independently of effects; finalize
never accepts review or rewrites original status/payload. #113 remains separate.
No new sync result/i18n code. Full lock/race rule and current callers:
../backend/uploads/README.md; mobile transport/check serialization is #246.

## Configuration table queries (#224)

These admin lists use page-number paging. Organization and parent authorization
precede search, filters, ordering and pagination. `search` uses DRF's
case-insensitive partial matching: terms must all match, each in any documented
search field; quoted phrases stay together. Blank search leaves the list unchanged;
NUL is a `400 validation_error` on `fields.search`.

`ordering` accepts comma-separated fields from the exact allowlist below, each
optionally prefixed with `-` for descending. Blank or unsupported terms return
`400 validation_error` on `fields.ordering`; mixed valid/invalid terms are rejected
together. Every ordering appends `id` ascending to resolve ties. PostgreSQL's native
null ordering applies (null last ascending, first descending). Search and ordering
on these lists do not filter detail lookups or mutation actions.

| List under `/api/v1/` | Search fields | Facets | Ordering fields | Default ordering |
| --- | --- | --- | --- | --- |
| `rule-parameters/` | `key` | `unit` (model enum), `value_type=integer\|decimal` | `key`, `unit`, `value_type`, `effective_from` (current projected version, nullable) | `key,id` |
| `rule-parameters/{key}/versions/` | `reason` | Existing `include_voided=true\|false` (default false); `status=scheduled\|in_force\|superseded\|voided` | `effective_from`, `created_at`, `value` | `-effective_from,-created_at,id` |
| `catalogs/` | `slug`, `label_es`, `label_en` | None | `slug`, `label_es`, `label_en` | `slug,id` |
| `catalogs/{slug}/items/` | `code`, `label_es`, `label_en` | `is_active=true\|false` (omitted: both) | `code`, `label_es`, `label_en`, `sort`, `created_at`, `usage_count` | `is_other,sort,code,id` |
| `devices/` | `label`, `serial`, `app_version`, `last_user.username` from a same-organization membership (active or historical) | Existing `is_revoked`, `user` (any historical device session) | `label`, `serial`, `app_version`, `last_seen_at`, `created_at` | `-created_at,id` |

`unit` values are `m`, `km_h`, `s`, `min`, `day`, `week`, `count`, `km_l`.
New choice facets reject blank/unsupported values; `is_active` accepts exactly
lowercase `true` or `false`. Rule history status never expands void visibility:
`status=voided` requires `include_voided=true` to return rows. Item availability is
independent of historical reference counts; filtering never changes catalog
revisions. Items always prepend `is_other` ascending, even for requested descending
orders, so protected Other stays last among matches. A search may omit Other.
Reorder still requires the complete active non-Other id set and the catalog version,
regardless of list query parameters. Field catalog/rules snapshots and their ETags
keep their existing contracts and do not acquire these table filters.

The existing geography identity lists retain their code search/ordering. Their
`quadrants/{id}/versions/`, `blocks/{id}/versions/` and
`sampling-points/{id}/versions/` actions now support the following independent
history query parameters after resolving the authorized parent:

| History | Filters | `ordering` (one field, optional `-`) | Default |
| --- | --- | --- | --- |
| Quadrant / block | `revision` (positive integer), `created_by` (UUID), `effective_from_from` (inclusive ISO datetime), `effective_from_before` (exclusive ISO datetime) | `revision`, `effective_from`, `created_at`, `created_by` | `-revision,id` |
| Sampling point | `version` (positive integer), `created_by`, the same datetime bounds, `is_retired=true\|false` | `version`, `effective_from`, `created_at`, `created_by`, `is_retired` | `-version,id` |

Both history styles append `id` ascending for ties and paginate after filtering.
An end bound at/before a start bound returns `400` with
`fields.effective_from_before` code `invalid_range`. Invalid UUIDs, dates, positive
integers, booleans and ordering choices use the existing coded validation envelope.
An unmatched author returns an empty history; an unknown or inaccessible parent
returns `404` before any history query. These immutable geography versions have no
void flag or free-text search field; geometry/location are not searched. Their
OpenAPI parameters describe history fields, without the identity-list filters.

Verified primitives: [DRF search and ordering filters](https://www.django-rest-framework.org/api-guide/filtering/)
and [Django queryset ordering](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#order-by).

## Shared conventions

| Topic | Convention | Status |
|---|---|---|
| Base path | `/api/v1/`. Field-only endpoints under `/api/v1/field/` (sync, catalog snapshot, rules snapshot, uploads). | Accepted |
| Naming | Plural kebab-case English nouns; actions as `POST /<resource>/{id}/<verb>/`. | Accepted |
| Organization | Resolved from the authenticated user's membership. Any `organization_id` in the body is ignored. Objects of another org → `404`. | Accepted |
| Multi-org users | Active org chosen with header `X-Organization: <slug>`; required only if the user has more than one active membership (else `400 organization_header_required`). A slug that is not one of the user's active memberships is always `403 no_active_membership`, even for users with one membership. Active = membership and organization both `is_active`. | Accepted |
| No delete | No `DELETE` on business data. `POST …/void/` with `{reason_code, reason?}`; responses carry `voided_at`, `voided_by`, `void_reason_code`, `void_reason`; lists exclude voided unless `?include_voided=true`. `PUT`/`PATCH` on a voided record → `409 already_voided`. Mobile uses a void event in the sync batch with the same semantics. | Accepted |
| Void reason (#32, #80) | Every void path resolves `reason_code` in the target organization's open `void-reason` catalog (one query). A missing or blank code is `required` on `reason_code`; unknown, foreign, missing-catalog or inactive choices return `void_reason_code_unknown` on that field. `other` requires nonblank `reason` (`void_reason_required_for_other` otherwise); the existing visible-character minimum (`VOID_REASON_MIN_LENGTH`, default 10) applies only to Other. Other codes allow an optional note, including an empty one, without a minimum. All nonblank notes are normalized (NFC, CRLF as LF), trimmed, checked for control/bidi characters and limited to 1000 characters. Invisible characters and fillers do not count toward the Other minimum (see `core/void_reason.py`). Text errors remain `void_reason_too_short` with `{min_length}`, `void_reason_invalid_characters`, and `max_length` with `{max_length}`. HTTP errors are `400 validation_error` with `fields.<field>: [{code, params}]`, never user text; validation precedes state checks. Both code and text are stored; old voids are backfilled as `other` with their original text. `GET /me/` still returns `limits: {void_reason_min_length, void_reason_max_length}`. In sync, unknown/foreign codes are rejected with `void_reason_code_unknown`; text errors use `invalid_payload` with `params.fields` and, when applicable, `params.field_params`. A code deactivated since the phone's snapshot lands `in_review` as `void_reason_code_deactivated`, with the target intact until supervisor acceptance (#22). Other void answers remain `409 already_voided`, state conflicts, `403` and `404`. | Accepted |
| Blocked actions | `409` + `{ "blocked_by": [{ "reason", "unblocked_by_role", "link" }] }`. | Accepted |

## Organization administration (#99)

`GET /centers/` is a page-number list of active centers visible to center.read,
with `{id, code, name}`, exact `?code=`, `?search=` and `?ordering=code|name`.
`GET /centers/{id}/` also resolves inactive historical centers in scope. Scope is
explicit per dimension: none denies, selected checks its UUID ids (empty denies),
all requires an explicit grant. A new center never expands selected. Permissions,
center and applicable quadrant must be covered by one effective profile grant
intersected with the membership. Org-only configuration checks its action code.
Selected quadrant ids now resolve to real organization/center-owned geography rows (#108); unresolved legacy ids never grant new access.

`GET/PATCH /organization/` reads or versions current name/timezone/languages/
epi_week/label_phone/support_contact. PATCH requires expected_revision; there is no
POST organization creation. `GET /roles/`, `PUT /roles/{id}/permissions/` accepts
`{permissions, scope, expected_revision}`. `GET/POST /memberships/` and
`POST /memberships/{id}/change-scope/` keep shared User identity; create accepts
`{user: UUID, profiles: UUID[], scope}`, change accepts
`{scope, expected_revision, profiles?: UUID[], is_active?: boolean}`. List reads use
role.read, writes role.update; organization settings use organization.read/update.
Membership filters are user, profiles, is_active; ordering/search are server-side.
Foreign or out-of-grant references return 404; absent action grants return 403.
Scope grants cannot exceed the actor's effective grant for the assigned action.
Government is portal.read only, never internal or mixed with internal profiles.

Revisions are monotonic; 409 stale_revision and last_administrator return safe
blocked_by entries. Concurrent administration is serialized per organization;
try-lock contention returns 429 administration_in_progress + Retry-After 1.
Every successful settings/role/membership change appends an immutable authored
configuration snapshot. Baselines and seeds have a null platform author.
