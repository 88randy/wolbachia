# M10 release and blocked release (#139)

P18/P19 open from actual assignments4 release work or the existing M07 QR/manual
router. Permits2 downloads own-courier device, explicit task/permit-version binding,
receipt custody, original/current lot safety and transit policy. Eligibility1
provides genuine training pins. Only these facts authorize a local capture route.
The DayStore bootstrap/delta/cursor transaction retains owner/session/scope
readiness and sequence floors. Missing or malformed sections and revocation never
grant capture or erase authored evidence. Schema20 appends retained drafts after
unchanged SQL1-19; a no-file draft already protects the phone's owner.

Raw quantity persists per keystroke and native actions flush that exact draft.
Camera/file I/O stays outside edit/projection queues. An already launched photo
can finish privately under a same-owner local lock; new actions and changed
owner/session/selection/scope cannot use that continuation. Undo removes only the
draft reference; private bytes remain retained and unenrolled until Save.

When a refreshed prerequisite repairs a blocked origin, an explicit restart in
the same active shift atomically retains the original draft and creates a new
UUID with current pins. Only raw quantity carries forward; photos and GPS must be
captured again. Superseded rows are immutable and cannot be saved or edited.
Starting work in a new shift leaves earlier drafts retained under their origin.

Save measures fresh foreground GPS, seals the actual capture time, rechecks
original/current prerequisites and local custody reservations, then atomically
enrolls the immutable event, assessment and evidence in the existing outbox/file
journal before showing phone-saved status. That worker alone owns verification,
JSON retry and final upload. Opening/release/closing JSON ordering never blocks
local Save. There is no online capture write, new grant, queue or inventory ledger.

Receipt selection follows the backend's first sufficient source order. A local
capture remains reserved until the server snapshot explicitly accounts its real
release event UUID or an exact-source terminal discard settles it. Immutable
in_review ingestion is not proof of stock consumption. Saved evidence and review
outcomes remain readable after the shift closes. Critical rejection preserves
the original UUID, payload and files, with no override.

Sample collection P20 is excluded: #117 is open and `sample.collect` is not
registered on the checked master. No sample API, queue or negative result is
invented. This limitation is recorded on #139.

GeoJSON Polygon uses longitude/latitude and covers exterior/hole boundaries.
GPS uses the explicit positive finite permit accuracy policy, without a fallback;
validity is [valid_from,valid_to). Missing facts fail closed. S10 deviations: the
actual manual-evidence-review policy requires photos, no planned quantity is
presented as stock, and actual UUIDs remain visible where human labels are absent.
Phone-saved, server-received and later-reviewed outcomes are separate.
