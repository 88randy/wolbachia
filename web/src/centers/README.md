# Center filter

The shell picker consumes backend-scoped centers and explicit /me/ scope. Selection is a convenience keyed by user id and organization slug. It never writes session state or expands grants. The exposed active center is derived synchronously from the stored preference intersected with explicit /me scope: all permits the stored id; selected requires that id; none/empty exposes no active center. Scope-invalid preferences are removed independently of center.read and the list query, without exposing them to queries while cleanup is pending. Cleanup compares the current stored value before writing, so it cannot erase a newer preference. List-based validation additionally reads all pages before invalidating a still-permitted remembered selection. Query context includes the selected center; authorization changes are published solely by session-controller.

Supported quadrant/motorcycle list and code queries apply URL center > active center > no filter. The generated contract has no center query for blocks or sampling points. The center-query test checks parameter precedence and unsupported endpoints; the center-filter test defers the A-to-B response and checks table/map isolation.

Scope-mode invariants without center.read/list access are covered by use-active-center.test.tsx. The deferred permission-change case in center-filter.test.tsx verifies that revoking center.read and narrowing A/B to B removes persisted A, old rows and A from subsequent request parameters/cache keys.
