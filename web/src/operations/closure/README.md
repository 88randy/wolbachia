# Quadrant closure (W33, issue #160)

Resolve the exact human quadrant code through the scoped collection before using
its UUID. Both `quadrant.read` and `quadrant.close`, explicit nonempty center and
quadrant scope, and an accepted current read are required to open this workspace.
The backend rechecks the paired action grant; `/me/` is only a UI projection.

Readiness is observational. Show every returned blocker and its required action,
including opaque blockers with no identity. No client operation clears blockers.
Only an unclosed, matching epoch with `can_close` and an empty blocker collection
can open the irreversible confirmation. Freeze its reviewed revision/version;
refreshing or changed evidence makes that confirmation unusable. A 409 refreshes
readiness and requires a new deliberate confirmation; no write is replayed.

The public contract has no trap counts, laboratory progress, responsible names,
removal action or closure reason. Display supplied opaque references and action
permissions without inventing routes or measurements. Close only sends the
documented `expected_revision`; its immutable receipt retains author and clocks.
Closing never publishes geometry or silently reopens a historical quadrant.

Session data uses the central organization query policy and guarded explicit
writes. Scope/record boundaries remount command state and remove obsolete cached
reads. Reason drafts belong to review and relocation, not the close contract.
